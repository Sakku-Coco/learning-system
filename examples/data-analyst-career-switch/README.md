# 示例：一个数据分析师的转型训练配置

> 这是一份**匿名化的真实配置**——本仓库的框架就是在这套配置下跑出来的（60+ 天）。
> 用途：展示"内核 + 配置"怎么落地。你的配置应该长得跟它不一样，因为你的目标和弱点不一样。

## 背景

- 学习者：3年+ 经验的业务数据分析师，实践强理论弱，Excel 思维，目标是转型更高阶的分析岗位
- 核心痛点（按配置演化的顺序）：
  1. SQL 理论不系统 → 从错题集驱动的 SQL 训练开始
  2. 干了活说不出价值（"埋金子"）→ 加入战绩日志 + 价值呈现训练
  3. 表达啰嗦、重点后置 → 长出第三个评审角色"结构教练"和独立的表达结构错题集
  4. 外语即时表达不稳 → 语言项进核心科目，隔天轮换

## 这份配置里值得注意的设计决定

- **及格线 7/10 + 连续2次**：不是拍脑袋——试过"一次过就推进"，两周后旧概念大面积遗忘，才收紧成连续2次
- **SQL 场景域绑定学习者的真实业务**：同样的 GROUP BY，用"算各区域回收率"出题比"统计每组数量"记得牢一个量级
- **三档练法**：转型训练跑在全职工作之上，没有兜底档的计划活不过第3周
- **弱点模式表不是一开始就有的**：第8节的"结论垫底"模式是训练到第4周、同一问题在3个不同场景出现后才立档的——这正是"一个点是噪音，一条线才是信号"规则的产物

## 演化时间线（机制是怎么长出来的）

| 阶段 | 加了什么 | 为什么 |
|------|----------|--------|
| 第1周 | 错题集 + 训练日志 | 基础盘 |
| 第2周 | 采访先行 + 一次一问 | agent 自作主张产出跑偏，用户疲劳 |
| 第3周 | 能力校准表（证据驱动） | agent 对水平的判断反复漂移，靠对话纠正太费劲 |
| 第4周 | 真实性来源分级 ✅/⚠️/🔧 | 发现 agent 会把编的业务流程讲得像真的 |
| 第5周 | "说得出口"关 | agent 写的面试故事书面腔严重，现场说不出口 |
| 第6周+ | 结构教练 + 表达结构错题集 | 外部真人反馈与 agent 诊断交叉指向同一根因：结构层问题 |
| 全程 | 动手前检查关卡 hook | 规则多了以后 agent 开始漏执行，靠 hook 每回合强制提醒 |
